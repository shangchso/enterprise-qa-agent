# 01 需求说明

## 1. 用户与目标

- **用户角色**：企业员工。
- **目标**：找到制度或产品问题的**可靠答案**。

## 2. 输入与材料

| 输入项 | 说明 |
| --- | --- |
| 问题 | 员工提出的自然语言问题 |
| 对话历史（可选） | 多轮追问时用于解析指代 |
| 合成 FAQ/制度 | 带文档 ID、版本日期的文档，见 `data/documents.json` |

## 3. 工具范围

1. **文档检索 document_search**：按关键词（含同义改写）检索相关片段。
2. **片段读取 fragment_reader**：读取原文片段用于回答与查证。

## 4. 交付结果

回答、引用文档 ID 与原文片段、资料缺口、任务状态。

## 5. 动态决策要求

模型根据检索结果选择**补充检索、读取原文、追问或停止**；资料冲突时
说明冲突并查证，**不凭空选一个答案**。

## 6. 成功标准（验收点）

| 编号 | 验收点 | 期望行为 |
| --- | --- | --- |
| AC1 | 明确答案 | 引用原文回答，带文档 ID |
| AC2 | 文档冲突 | 列出冲突与引用，请求确认适用制度 |
| AC3 | 资料外问题 | 返回资料缺口，不编造 |
| AC4 | 改写相似问题 | 同义改写仍能命中正确文档 |
| AC5 | 上下文追问 | 结合历史解析指代并回答 |
| AC6 | 工具失败 | 阻断并如实返回 |

## 7. 边界与红线

- 无依据回答或错误引用属于关键缺陷。
- 冲突未查证前不擅自选择（如不能直接回答 15 天）。
- 不提交真实密钥或隐私数据。
